# Сервис игровых комнат

GitHub Pages хранит интерфейс, картинки и фрагменты. Этот отдельный сервис хранит комнаты в памяти и принимает обычные WebSocket-соединения: 50 участников плюс ведущий. Время ответа и очки считает сервер. WebRTC, STUN и TURN ему не нужны.

Подготовлен и проверен локально. Публичный адрес ещё не настроен: `RELAY_URL` в `connection.mjs` пуст. Пока он пуст, опубликованный сайт использует прежний PeerJS. Для production нужно развернуть сервис и пересобрать frontend с его адресом.

## Локальный запуск

Из корня репозитория:

```powershell
npm ci
$env:ALLOWED_ORIGINS='http://127.0.0.1:8767,https://mupamuc.github.io'
npm run server
```

Сервис слушает `127.0.0.1:8890`. Проверка: `GET /health`. WebSocket: `/rooms`.

Для localhost с параметром `?transport=local` frontend выбирает `ws://127.0.0.1:8890/rooms`; при локальной проверке его нужно разрешить в CSP только в локально отдаваемом HTML. Обычный локальный адрес проверяет тот же PeerJS, что и публичный сайт. В production сборка добавляет в CSP точный WSS-origin из `RELAY_URL`.

## Размещение на VPS

1. Отдельная директория и контейнер, без изменений других приложений:

```sh
BUILD_SHA=$(git rev-parse HEAD) docker compose -f server/compose.yaml up -d --build
curl --fail http://127.0.0.1:8890/health
```

2. Выделенный HTTPS-поддомен с обратным прокси. Пример отдельного блока Caddy; фактическое имя домена выбирается при развёртывании:

```caddyfile
quiz-rooms.example.com {
    reverse_proxy 127.0.0.1:8890
}
```

3. Записать фактический `wss://quiz-rooms.example.com/rooms` в `RELAY_URL`, запустить `npm run build`, опубликовать frontend на Pages. Публичный endpoint должен иметь действительный TLS-сертификат.

4. Проверить публичный `/health`, подключение ведущего и двух участников из разных сетей, затем нагрузку 50 клиентов. Локальная проверка не подтверждает доступность VPS из мобильной сети.

## Поведение

- До 50 игроков. 51-й получает понятный отказ. Никакой пароль или регистрация на стороннем сервисе не требуется.
- Профиль игрока восстанавливается по случайному токену в его браузере; токен не передаётся другим участникам в снимках состояния. Случайный токен ведущего разрешает ему управлять комнатой и восстанавливать кратко потерянное соединение.
- До старта все загружают картинку, после чего начинается общий отсчёт. Картинка и варианты закрыты интерфейсом до старта; правильная песня отсутствует в снимках комнаты до открытия ответа. Каталог с картинками публичен, поэтому это игра для компании, а не защищённый экзамен.
- При потере связи ведущего раунд ставится на паузу до 90 секунд. Возврат того же соединения с токеном сохраняет комнату и сдвигает отсчёт на время паузы. Клиент пытается вернуться три раза, затем показывает кнопку восстановления.
- При выходе ведущего комната закрывается. При перезапуске сервиса комнаты теряются. После обновления вкладки ведущего текущий интерфейс не восстанавливает его роль; нужна новая комната.
- Комната живёт не более четырёх часов. До 100 одновременных комнат; этот общий лимит не проходил нагрузочную проверку.
- Только указанные в `ALLOWED_ORIGINS` браузерные origins могут открыть WebSocket. Входящие сообщения ограничены 4 КиБ и 30 сообщениями в секунду на соединение. Сервер прекращает соединение с медленным читателем и проверяет живые сокеты каждые 30 секунд.
- Контейнер работает без root и без доступа к музыкальной библиотеке, базе караоке и другим приложениям. В него включены только код и каталог с названиями песен.

```sh
npm test
```

Тесты сервиса устанавливают 50 настоящих локальных WebSocket-соединений, проверяют ограничение, серверный подсчёт, скрытый ответ, возврат игрока, потерю связи ведущего, его токен и ограничения origin. Docker-сборка и работа на VPS требуют отдельной проверки при развёртывании.
